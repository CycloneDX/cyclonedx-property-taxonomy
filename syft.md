# `syft` Namespace Taxonomy

This is the namespace for properties emitted by [Syft](https://github.com/anchore/syft), a CLI tool and Go library for generating Software Bill of Materials (SBOMs) from container images and filesystems.

The official rules and processes apply - see [parent document](../README.md).

----

_Boolean value_ are `true` or `false`; case sensitive.

| Namespace | Description |
|-----------|-------------|
| `syft:package` | Namespace for properties that describe how the package (component) was discovered by Syft. |
| `syft:location` | Namespace for the filesystem locations that lead to the discovery of the package. One property pair per location, indexed starting at `0`. |
| `syft:metadata` | Namespace for ecosystem-specific metadata of the package. The available property names depend on the package type identified by `syft:package:metadataType`. |
| `syft:cpe23` | Property for additional Common Platform Enumeration (CPE) entries of the component. |
| `syft:distro` | Namespace for operating system (distribution) information; used on components of type `operating-system`. |
| `syft:image` | Namespace for container image specific properties. |
| `syft` | Properties used in non-CycloneDX output formats generated by Syft. |

## `syft:package` Namespace Taxonomy

| Property | Description |
|----------|-------------|
| `syft:package:foundBy` | Name of the cataloger that discovered the package. May appear once. Example value: `apk-db-cataloger` |
| `syft:package:language` | Programming language the package was written in. May appear once. Example value: `go` |
| `syft:package:type` | Ecosystem or package type the package belongs to. May appear once. Example value: `apk` |
| `syft:package:metadataType` | Identifier of the metadata structure attached to the package; determines the available `syft:metadata:*` property names. May appear once. Example value: `apk-db-entry` |

## `syft:location` Namespace Taxonomy

Locations are encoded as pairs of properties per index (`<INDEX>` is a zero-based integer):

| Property | Description |
|----------|-------------|
| `syft:location:<INDEX>:path` | Real path within the filesystem that lead to the discovery of the package. May appear once per `<INDEX>`. Example value: `/lib/apk/db/installed` |
| `syft:location:<INDEX>:layerID` | Digest of the container image layer the location belongs to. Only present when scanning container images. May appear once per `<INDEX>`. Example value: `sha256:34884abbe92863fce933ed7c39c0e045631af0ed86d5cc0dfbdf9fdca426ce3c` |

## `syft:cpe23` Property Taxonomy

| Property | Description |
|----------|-------------|
| `syft:cpe23` | Additional CPE 2.3 entry of the component in formatted string binding. The most-specific CPE is emitted as the component's `cpe` field; every further CPE is emitted as this property. May appear multiple times with different values. Example value: `cpe:2.3:a:alpine-baselayout:alpine_baselayout:3.7.2-r1:*:*:*:*:*:*:*` |

## `syft:distro` Namespace Taxonomy

Used on the `operating-system` component of a CycloneDX document.

| Property | Description |
|----------|-------------|
| `syft:distro:prettyName` | Operating system name in a format suitable for presentation to the user. May appear once. Example value: `Alpine Linux v3.24` |
| `syft:distro:id` | Operating system identifier, excluding any version information. May appear once. Example value: `alpine` |
| `syft:distro:idLike:<INDEX>` | Identifiers of operating systems that are closely related to the local operating system. May appear multiple times with different values. Example value: `alpine` |
| `syft:distro:versionID` | Operating system version, excluding any OS name information or release code name. May appear once. Example value: `3.24.1` |
| `syft:distro:versionCodename` | Release code name of the operating system version. May appear once. |
| `syft:distro:buildID` | String uniquely identifying the system image originally used as the installation base. May appear once. |
| `syft:distro:imageID` | Identifier of the system image. May appear once. |
| `syft:distro:imageVersion` | Version of the system image. May appear once. |
| `syft:distro:variant` | Specific variant or edition of the operating system. May appear once. |
| `syft:distro:variantID` | Identifier of the specific variant or edition of the operating system. May appear once. |
| `syft:distro:extendedSupport` | Whether there was evidence of extended support found. _Boolean value_. If the property is missing, then assume the value to be `false`. May appear once. |

## `syft:image` Namespace Taxonomy

| Property | Description |
|----------|-------------|
| `syft:image:labels:<KEY>` | Label of the container image being scanned. May appear multiple times with different values. |

## `syft` Property Taxonomy (non-CycloneDX outputs)

These properties appear in other output formats generated by Syft (e.g. GitHub dependency snapshots):

| Property | Description |
|----------|-------------|
| `syft:distro` | Package URL (`purl`) representation of the scanned operating system distribution. May appear once. Example value: `pkg:generic/alpine@3.20.2?like=alpine` |
| `syft:filesystem` | Identifier of the filesystem a manifest was found on (relevant when scanning multi-filesystem sources). May appear once. |

## `syft:metadata:*` Namespaces

The property names under `syft:metadata` mirror the fields of the ecosystem-specific
metadata structures attached to a package. Which subset appears depends on
`syft:package:metadataType`; values are stringified field values, list items are
indexed by position (e.g. `syft:metadata:pullDependencies:0`).

Commonly seen namespaces include:

| Namespace | Related `metadataType` | Property names (leaf segments) |
|-----------|------------------------|--------------------------------|
| `syft:metadata` (Alpine) | `apk-db-entry` | `originPackage`, `size`, `installedSize`, `pullDependencies:<INDEX>`, `provides:<INDEX>`, `pullChecksum`, `gitCommitOfApkPort` |
| `syft:metadata` (Debian) | `dpkg-db-entry` | `source`, `sourceVersion`, `installedSize` |
| `syft:metadata` (RPM) | `rpm-db-entry` | `epoch`, `release`, `sourceRpm`, `signatures:<INDEX>`, `size`, `modularityLabel` |
| `syft:metadata` (Go binary) | `go-module-buildinfo-entry` | `architecture`, `goCompiledVersion`, `h1Digest`, `mainModule`, `goCryptoSettings:<INDEX>`, `goExperiments:<INDEX>`, `goBuildSettings` |
| `syft:metadata` (Java archive) | `java-archive` | `virtualPath`, `groupID`, `artifactID` |
| `syft:metadata` (Linux kernel) | `linux-kernel-archive` / `linux-kernel-module` | `name`, `architecture`, `version`, `extendedVersion`, `buildTime`, `author`, `format`, `rwRootFS`, `swapDevice`, `rootDevice`, `videoMode`, `sourceVersion`, `path`, `description`, `license`, `kernelVersion`, `versionMagic`, `parameters`, `type` |
| `syft:metadata` (GGUF model) | `gguf-file-header` | `ggufVersion`, `fileSize`, `architecture`, `quantization`, `parameters`, `tensorCount`, `header`, `metadataHash`, `parts` |
| `syft:metadata` (SafeTensors model) | `safetensors-model-info` | `format`, `architecture`, `quantization`, `parameters`, `tensorCount`, `totalSize`, `shardCount`, `userMetadata`, `metadataHash`, `parts` |

> Note: this list reflects the property names emitted by recent versions of Syft.
> New metadata types may introduce additional `syft:metadata` namespaces.
